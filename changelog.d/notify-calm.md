### Fixed

- **A conversation is one notification, not one per message.** In the Windows desktop app every message that arrived while you were in another window raised a Windows notification of its own, so a lively channel or DM filled the screen and the notification centre (Windows' own toasts carried nothing to tell them apart). Now each channel and each DM has one notification that keeps count, such as *#general · Lads: alice and 2 others: 5 new messages*. It pops up for the first message; while the conversation goes on, new messages change it where it is, without popping up again or making a sound (Púca's own message sound plays only when it pops up). After a quiet minute, or once you have been back in Púca and left again, the next message pops it up again. A DM pops up at most once a minute while it goes on, and so does an @mention of you in the channel you have open, even mid-conversation. Reading the conversation in Púca takes its notification out of the notification centre; clicking it while it is on screen opens that conversation. People joining a server are one notification per server too. Notifications still never say what a message says, and nothing shows while you are using Púca. **Settings → Notifications → Group notifications by conversation** is on by default; turning it off brings back one per message. The web app's notifications are grouped the same way, though how a browser draws a replaced notification is up to it. The desktop app, full and Lite, needs this version's installer; Android's notifications are unchanged (they already replace one another, one per server and one per DM).
